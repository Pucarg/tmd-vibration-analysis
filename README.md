# Tuned Mass Damper Vibration Analysis

Python tools for post-processing vibration measurements from a scale structural
model fitted with a mass-spring tuned mass damper (TMD).

Developed in the context of Pablo Úcar Gargallo's undergraduate thesis,
**Caracterización experimental de un sistema de amortiguación de masa sintonizada
para la mitigación de vibraciones estructurales**, Universitat Politècnica de
València, academic year 2025/2026.

The experiment compared nine damper configurations with the undamped model.
PULSE/accelerometer measurements provided the quantitative reference; Tracker
video analysis supplied a complementary time and frequency comparison. The
undamped model's reference frequency was approximately **5.6 Hz**. That value is
experimental context: neither script hard-codes it as the frequency to detect.

## What the scripts do

| Script | Input | Processing | Output |
| --- | --- | --- | --- |
| `PlotPulse.py` | PULSE frequency-domain text exports | Read metadata and indexed numeric rows; convert acceleration; detect global peaks; compare curves | One comparison PNG, a peak-summary table in the figure, and one clean CSV per valid input |
| `PlotTracker.py` | Tracker time/acceleration text export | Convert acceleration; optionally rescale timestamps; interpolate uneven sampling; subtract the mean; calculate a one-sided FFT | Separate time-domain and frequency-domain figures, each with a results table |

PULSE exports already contain spectra, so `PlotPulse.py` does not apply another
FFT. `PlotTracker.py` reads acceleration already calculated by Tracker; it does
not analyze video or derive acceleration from displacement. These scripts do
not calculate spring stiffness, tune a TMD, or simulate the structure.

## Installation

Use Python **3.11 or later**, preferably Python 3.12. This package was tested
with **Python 3.12.14, NumPy 2.3.5, and Matplotlib 3.10.8**. Other Python versions
have not been tested here. Only NumPy and Matplotlib are external dependencies;
the remaining imports belong to Python's standard library.

Open a terminal in the extracted repository folder:

```bash
python -m venv .venv
```

Activate the environment in Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Or in macOS/Linux:

```bash
source .venv/bin/activate
```

Then install the dependency versions used for validation:

```bash
python -m pip install -r requirements.txt
```

On systems where the command is `python3`, use it instead of `python`.

## PlotPulse.py: input format and settings

The supported PULSE export is a Latin-1 text file with:

- A first line of the form `Header Size: N`, where N includes that line.
- Header fields such as `Signal` and `SignalUnit`; `PowerUnit` is a fallback
  field name, but its contents must still describe acceleration amplitude.
- Numeric rows with exactly **three whitespace-separated fields**:
  positive integer index, frequency in Hz, acceleration magnitude.
- Comma or point decimal marks. Frequencies must increase strictly, and
  frequencies and magnitudes must be non-negative and finite.

For example, the data portion may contain literal tab separators:

```text
1    0,000000    0,001000
2    0,100000    0,002000
3    0,200000    0,003000
```

Only `m/s²`, `cm/s²`, `mm/s²`, and `g` are converted; equivalent spellings such
as `m/s^2`, `m/s**2`, and `m/s2` are accepted. The retained approximate gravity
conversion is 1 g = 981 cm/s². All plotted/exported accelerations use cm/s².
Missing or unknown units, velocity spectra, and power spectral densities are
rejected. The program does not convert between peak and RMS amplitudes: check
the PULSE acquisition/export settings before comparing measurements.

Process one file or overlay several, quoting paths that contain spaces:

```bash
python PlotPulse.py "data/raw/Sistema no atenuado.txt"
python PlotPulse.py "data/raw/Sistema no atenuado.txt" "data/raw/Sistema de muelles 1.txt"
```

Edit the `CFG` dictionary near the top of `PlotPulse.py`:

| Setting | Meaning | Default |
| --- | --- | --- |
| `titulo` | Figure title; `None` uses metadata | Spanish comparison title |
| `etiq_y` | Y-axis text; changing it does not change the values' units | Acceleration in cm/s² |
| `escala_y_log` | Logarithmic y axis; zero values are not visible on a log axis | `False` |
| `rango_x` | Visible frequency limits in Hz | `None` (automatic) |
| `rango_y` | Visible acceleration limits in cm/s² | `[0, 40]` |
| `guardar_png`, `guardar_csv` | Enable each export | Both `True` |
| `dpi` | PNG resolution | `150` |
| `carpeta_salida` | Output directory, created if needed; e.g. `"outputs"` | `None` (beside inputs) |
| `nombre_png` | Comparison image filename | `"comparison.png"` |
| `archivo_referencia` | Exact loaded baseline filename or unique full path | `None` (largest loaded peak) |

For an explicit undamped reference, include that file in the inputs and set:

```python
"archivo_referencia": "Sistema no atenuado.txt",
"carpeta_salida": "outputs",
```

Without command-line paths, the optional `rutas_fijas` list in `main()` is used.
If that list is empty, all `.txt` files in the **current working directory** are
attempted. Explicit paths are the clearest way to avoid unrelated text files
such as `requirements.txt`. For an IDE's Run button, edit `rutas_fijas`, for
example `rutas_fijas = [Path("data/raw/Sistema no atenuado.txt")]`.

The clean CSV columns are `Frecuencia_Hz,Aceleracion_cm_s2`, with comma field
separators and point decimal marks. Inputs with the same stem share an output
CSV name when using one output directory; use distinct names to avoid replacing
one result with another. Repeated runs overwrite matching output filenames.

### Meaning of the reduction table

Each input is represented by its **global maximum spectral magnitude**, even
when the peak lies outside the displayed axes. The calculation is:

**Reduction (%) = 100 × (reference peak − configuration peak) / reference peak**

With `archivo_referencia=None`, the reference is the largest peak among the
successfully loaded inputs, preserving the original script's behavior. This
does not automatically identify the undamped model. An explicit reference
avoids that assumption; a peak above it produces a negative reduction. A zero
reference gives `N/D` because a percentage reduction is undefined.

This compares global peaks, potentially at different frequencies. It does not
extract every curve's value specifically at 5.6 Hz. In the thesis, comparison
records were acquired under excitation at the undamped model's reference
frequency, and their spectral maxima were compared (section 4.3.3). Keep that
excitation condition distinct from the location of each spectrum's peak.

## PlotTracker.py: input format and settings

Export the intended acceleration component from Tracker as the **first two
tab-separated columns**, ordered as time in seconds and acceleration in m/s².
Use UTF-8 (with or without a BOM) and **point decimal marks**. For example:

| t (s) | a_x (m/s²) |
| --- | --- |
| 0.00 | 0.010000 |
| 0.02 | 0.087647 |

The table illustrates the columns; the actual text file must contain literal
tabs, as in `examples/tracker_acceleration.txt`. Track names and column-label
headers are ignored, as are rows missing either value or containing nonnumeric
fields. Extra columns are ignored. At least two valid paired samples are
required, with finite values and strictly increasing, non-duplicate timestamps.
There is no unit autodetection: input acceleration is always multiplied by 100.

```bash
python PlotTracker.py data/raw/tracker_measurement.txt outputs/system_1
python PlotTracker.py data/raw/tracker_measurement.txt outputs/system_1 --freq-max 25 --acel-max-tiempo 45 --acel-max-frecuencia 40
python PlotTracker.py --help
```

The second positional argument is an optional output base. Without it, results
are written beside the input. By default, PNG is used; an explicit
Matplotlib-supported extension such as `outputs/system_1.svg` changes the output
format. Parent directories are created automatically. Matching outputs are
overwritten on subsequent runs.

| Setting | Location | Default |
| --- | --- | --- |
| Input path | First argument, or `ARCHIVO_ENTRADA` for IDE execution | Empty fallback |
| Output base | Optional second argument | Input path without its extension |
| Time multiplier | `MULTIPLICADOR_TIEMPO` constant | `1.0` |
| Frequency display limit | `--freq-max` or `FREQ_MAX_DEFAULT` | 25 Hz |
| Time plot's symmetric acceleration limit | `--acel-max-tiempo` or `ACEL_MAX_TIEMPO_DEFAULT` | ±45 cm/s² |
| Spectrum's acceleration limit | `--acel-max-frecuencia` or `ACEL_MAX_FRECUENCIA_DEFAULT` | 40 cm/s² |

For IDE execution, set `ARCHIVO_ENTRADA = "data/raw/tracker_measurement.txt"`.
On Windows, use a raw string such as `r"C:\measurements\tracker.txt"` for
backslash paths, or use forward slashes. Relative paths in either script are
resolved from the current working directory, not necessarily the script folder.

### FFT and interpretation

- Uneven sampling triggers linear interpolation using the median time step.
  The generated grid excludes the final endpoint, following the original
  algorithm. Review missing frames: interpolation does not recover lost data.
- The mean acceleration is subtracted before `numpy.fft.rfft`. Magnitudes are
  divided by the sample count; interior positive-frequency bins are doubled,
  while DC and the even-length Nyquist bin are not doubled.
- The result is a **one-sided peak amplitude spectrum**, not RMS, PSD, or an
  input/output frequency response function. There is no explicit tapering
  window (the record has an implicit rectangular window), smoothing, or zero
  padding. Off-bin sinusoids can leak into nearby bins and have underestimated
  peak amplitudes. The bin spacing is **Δf = 1 / (N × Δt)**, and the Nyquist
  frequency is **1 / (2 × Δt)**.
- The dominant bin is selected over all frequencies above zero, independently
  of the displayed axes. Its frequency is a bin estimate, without sub-bin
  interpolation. A forced-response peak alone does not establish a structure's
  natural frequency. A stationary record has no meaningful dominant oscillation.
- The time table reports **(maximum − minimum) / 2**. This half peak-to-peak
  range is distinct from maximum acceleration, maximum absolute acceleration,
  RMS, and the amplitude of an individual FFT component.
- `MULTIPLICADOR_TIEMPO` rescales timestamps and FFT frequencies only. It does
  not recompute the acceleration exported by Tracker, and it cannot repair
  aliasing. Leave it at 1.0 unless an independent timing check justifies a
  correction; check the time base in Tracker and re-export acceleration when a
  physically consistent timing correction is required.

Compare PULSE and Tracker amplitudes only after checking the measured component,
units, acquisition conditions, and amplitude convention. The thesis treats
Tracker as complementary, rather than using it to replace PULSE's quantitative
reference.

## Validation

Run the included tests from the repository root:

```bash
python -m unittest discover -s tests -v
```

Tests cover unit prefixes, PULSE parsing, explicit/largest-peak reductions,
sinusoidal FFT amplitude/frequency, Nyquist scaling, offset removal, time
rescaling, interpolation, and invalid timestamps. Both command-line workflows
were also run on the synthetic inputs, and the resulting PNG/CSV files were
checked. The original experimental exports were not supplied, so those records
have not been rerun or independently validated.

For unattended PULSE execution, use a noninteractive Matplotlib backend:

```bash
MPLBACKEND=Agg python PlotPulse.py examples/pulse_baseline.txt examples/pulse_with_tmd.txt
```

In PowerShell, set `$env:MPLBACKEND = "Agg"` before the ordinary command.
`PlotTracker.py` already selects this backend internally.
